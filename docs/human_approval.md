# Human Approval Workflow

## Overview
Every recommendation generated by the system starts with `Approval_Status = PENDING`. Operators can APPROVE, REJECT, or OVERRIDE individual recommendations through the API or dashboard.

## Approval States
| Status | Meaning |
|---|---|
| `PENDING` | Awaiting human review |
| `APPROVED` | Operator confirmed the recommendation |
| `REJECTED` | Operator declined the recommendation |
| `OVERRIDDEN` | Operator applied a manual decision with a documented reason |

## High-Impact Recommendations
The system flags recommendations as **High-Impact** under the following configurable conditions (in `src/api/db.py`):

| Condition | Default Threshold |
|---|---|
| Service Urgency | `Critical` |
| Recommended Quantity | >= 20 units |
| Estimated Transfer/Purchase Cost | >= INR 50,000 |

High-impact recommendations display a warning banner in the dashboard and require deliberate human confirmation before approval.

## Override Policy
- Override **always requires a non-empty `override_reason`**.
- Reason is persisted in the `approvals` SQLite table for full audit traceability.
- The API returns `HTTP 400` if `override_reason` is empty or whitespace.

## Audit Trail
All decisions are stored in `outputs/approvals.db` (SQLite). Each record contains:

| Field | Description |
|---|---|
| `recommendation_id` | Unique recommendation identifier |
| `status` | Current decision status |
| `original_recommendation` | Full JSON snapshot of recommendation |
| `override_reason` | Operator-provided justification (if overridden) |
| `timestamp` | UTC timestamp of the decision |
| `is_high_impact` | Boolean flag for high-impact threshold |
